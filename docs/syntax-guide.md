# TextUnitTest Syntax Guide

This guide explains how to write readable TextUnitTest suites in Markdown.

## Basic Pattern

Every suite follows the same broad pattern:

1. Start with a suite title using `#`.
2. Add one or more test cases using `##`.
3. Under each test heading, write one rule per line using `Key: Value`.

Example:

```md
# Release Notes Checks

## Ensure version is present

Target: release-notes.txt
Require: "Version:"
```

## Multiple Tests Per File

TextUnitTest suites are designed to group related checks in a single Markdown file.

Example:

```md
# Basic Validation Tests

## Ensure version exists

Target: sample-output.txt
Require: "Version:"

## Ensure no errors exist

Target: sample-output.txt
Reject: "ERROR"
```

Each `##` heading starts a new test case.

## Rule Formatting Rules

- Write each rule on its own line.
- Use the exact `Rule Name: Value` format.
- Keep rule names in title case.
- Include one `Target:` rule per test.
- Add `Fail:` when you want a business-friendly error message.

## Quoting Rules

Literal text should be wrapped in double quotes.

Examples:

```md
Require: "Version:"
Reject: "ERROR"
Starts With: "Quarterly Report"
```

Regular expressions should use slash delimiters.

Examples:

```md
Regex: /Build ID: \d+/
Reject Regex: /Status:\s+FAIL/
```

## Location Rules

Use location rules when you want to validate only part of a file.

Examples:

```md
Between: "Welcome" and "Copyright"
After: "Summary"
Before: "Generated by Internal Reporting"
```

These rules narrow the active search area before assertions are checked.

## Count Rules

Use `Count:` when exact match totals matter.

Examples:

```md
Count: 2 of "Line Item:"
Count: 1 matches /Started:\s+\d{4}-\d{2}-\d{2}T/
```

## Readability Tips

- Keep test names specific and outcome-focused.
- Prefer small, single-purpose tests.
- Use `Fail:` for messages a non-technical reviewer can understand quickly.
- Group related tests in the same suite file.

## Recommended Style

```md
# Invoice Validation Suite

## Ensure version number exists

Target: invoice.txt
Require: "Version:"
Between: "Welcome" and "Copyright"
Fail: Version number missing from header
```

This format stays readable in pull requests, code reviews, and CI logs.
